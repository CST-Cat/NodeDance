# S02：Agent注册、身份与通信可靠性

**前置阶段：** S01。  
**估算：** 7–10 个开发日。  
**当前状态：** `NOT_READY`。原11项命名用例和10项补充用例已有真实Core/Agent测试；阶段仍需连续三轮通过、systemd实测、受影响S01回归、amd64/arm64 GitHub Actions及根审阅。一次本地综合运行曾在默认租约物化时间上发现30.000358秒，因此不能登记为阶段通过；当前口径改为按有效租约期限判定对外状态，并单独记录SQLite异步物化延迟。

## 实施范围、样例和阶段门槛

Core 创建绑定节点、默认10分钟一次性的注册凭据；注册后分配独立设备身份，Core 仅保存长期凭据验证摘要；Agent 安全持久化凭据；实现协议版本、能力声明、5秒心跳、最多30秒失联判断、退避重连、连接代际、凭据轮换和撤销；提供注册及 systemd 安装命令。三节点身份不混用，重启后稳定复连，断网/重启后新代际同步，Agent 不新增管理监听端口。共享长期Token、日志泄露凭据、默认跳过TLS、旧代消息覆盖新状态、浏览器离线导致采集停止均驳回。

## 补充用例及触发原因

补充用例增强原11项验收，不替换或合并任何原始ID。每个用例均由`go test -json`生成独立命名事件，并由验收脚本写入逐项日志。

### `S02-SUP-01` — 未知但语法合法的能力。

同版本Agent声明Core尚不支持的合法能力字符串；真实Core仍完成握手，但WELCOME不协商该能力。这确保后续S03/S04新增能力不会使旧Core拒绝同协议Agent。

### `S02-SUP-02` — 仅pending凭据的恢复。

在Core仅保存pending verifier、尚未提交轮换的边界停止Agent并执行身份查询。Agent必须保留旧active和本地pending凭据，随后使用同一rotation ID完成轮换。

### `S02-SUP-03` — 丢失WELCOME后的普通重启恢复。

TLS代理丢弃Core已经提交的轮换WELCOME；正常`nodedance-agent run`重启后以pending凭据读取Core的active身份、持久晋升凭据，再执行第二次实际轮换。该流程防止遗留旧rotation ID永久阻止下一次轮换。

### `S02-SUP-04` — 真实systemd manager字面路径和服务用户。

GitHub Linux CI中的独立systemd manager启动生成单元，使用实际`systemctl`执行携带空格、`$`、`%`及引号的路径探针，比较进程收到的参数和实际UID；另检查未显式指定用户及配置归属不匹配时拒绝。`systemd-analyze verify`只作额外语法检查。

### `S02-SUP-05` — WSS租约精确边界。

真实TLS/WSS Core使用生产30秒租约值和受控逻辑时钟。deadline−1ms的HTTP状态仍为online且Heartbeat获得ACK；精确deadline的Heartbeat不获ACK，之后generation被废弃。

### `S02-SUP-06` — 生产默认5秒心跳和30秒失联。

真实Core及三Agent按生产时钟运行，测量两个连续心跳间隔；切断实际Agent WebSocket后记录最后有效Heartbeat、网络故障、有效租约截止、Core API判定时间和异步SQLite物化时间。其验收口径是不在有效租约到期后对外返回online；异步物化延迟独立报告，不伪称为截止时间。

### `S02-SUP-07` — 注册响应丢失后的设备身份恢复。

真实Core已事务提交enrollment后，由TLS代理仅丢弃一次HTTP响应；Agent只能使用预先保存的设备凭据查询原身份，不能重放enrollment token。

### `S02-SUP-08` — 清理延迟时仍按有效期限返回状态。

延迟后台sweeper/watchdog的SQLite状态物化，通过管理员认证后的真实Core API在deadline−1ms及精确deadline查询。API必须提供`leaseValidUntil`和`serverTime`；有效期内为online，精确截止时为offline，即使SQLite状态仍暂时为online。随后迟到Heartbeat必须被拒绝。该用例固定30秒值，并验证因本地首次测量发现异步物化晚于截止而补充的对外状态合同。

### `S02-SUP-09` — 快速重连替换旧lease watcher。

真实Agent普通断开后，Core必须继续保留该generation的到期watcher；更高generation通过认证连接后，Core立即取消并等待旧watcher退出，再只保留当前Agent一个lease watcher。之后Agent进程再次重连，验证watcher仍不会累积。普通断开不能提前改变30秒租约状态。

### `S02-SUP-10` — Core关闭时join已断开的lease watcher。

真实Core/WSS Agent普通断开后，确认当前到期watcher仍运行；调用`Core.Close`后必须取消并等待该goroutine，清空watcher owner map，且在所有watcher退出后才关闭SQLite。
