# S16：Agent手动与自动更新

**前置阶段：** S15。  
**估算：** 7–10 个开发日。  
**候选状态：** `NOT_READY`；本地 helper/API/UI 检查通过不等于正式阶段验收通过。

## 实施范围、样例和阶段门槛

发布清单带版本、架构、校验值、协议范围和可信签名；下载暂存、容量检查、原子切换和旧版本保留；独立更新助手与开机恢复入口负责失败回滚；自动更新默认关闭，支持窗口、批次和单节点放行；活动任务/传输期间推迟；版本/连接验证失败时本地回滚；持久记录每个更新阶段；旧Agent初次升级可由安装脚本或SSH完成。无签名、覆盖旧程序无备份、唯一回滚依赖新进程、失败身份丢失或一节点失败后继续批量升级均驳回。

## 已实现候选范围

- Agent 发布 manifest 使用 Ed25519 签名，包含版本、Linux 架构、SHA-256、字节数、协议兼容范围和 Core 版本范围。Core 只接受受信公钥验签通过的发布；Agent 再验证签名、哈希、大小、架构和兼容范围。
- `nodedance-release keygen` 生成独立签名密钥；`sign` 从 `0600` 私钥文件签名已构建的 Agent。Core 通过启动参数 `--agent-update-public-key` 或环境变量 `NODEDANCE_AGENT_UPDATE_PUBLIC_KEY` 配置受信公钥。私钥不经 CLI 参数传递，也不应放入 Core/Agent 产物。
- Core 登录后提供 `/api/v1/updates` 的发布上传、手动更新、自动窗口、批大小、暂停/恢复及任务历史入口。Agent 下载端点要求 TLS 和已登记设备凭据；浏览器管理员写请求沿用现有 Session/CSRF 保护并写审计。
- 更新任务、发布及策略保存在 SQLite S16 候选迁移 v7；此编号仅适用于基于 S15 v6 的本候选分支，集成时必须由 integration owner 按集成分支最高迁移号追加，不得重写既有迁移。
- systemd 安装会把 Agent 版本放入私有版本目录，并建立稳定 helper 和 `bin/current` 符号链接。更新先下载至临时目录，检查容量、签名、大小及摘要，fsync 后记录 journal；候选启动失败、候选进程启动后退出或确认超时，由仍运行的旧 helper 本地回滚，不依赖 Core。已确认版本只清理 journal，不回退。
- helper 子进程报告候选版本、重新连接后 Core 才把任务确认成功。Core 重启时将未决派发任务恢复为 deferred，再依据 Agent 实际版本进行协调；自动 campaign 只选择在线且架构与所选发布包相符的 Agent，并按持久化顺序串行放行节点，只有前一节点已确认成功后才调度下一节点，失败时暂停余下节点。自动更新默认关闭。
- Agent 有未完成控制任务或数据流时调度器会延后更新。该检查在候选实现中存在，但当前 focused suite 未在完整真实终端/文件/容器任务期间执行，因此对应规范项不因此计为通过。
- 已有 updater helper 的 Agent 能在线升级。尚不支持 updater 的旧 Agent 必须由当前安装脚本/SSH 运维流程先重新安装 S16 版本并安装 systemd helper；不假设旧进程能执行更新协议。
- 本地 helper 集成测试使用临时目录、真实 Linux 子进程和本地 shell fixture 验证状态机。它不等价于真实 systemd unit、重启 VM、多个实际 Agent 或真实 Core 断网验收。

## 签名与安装样例

```bash
nodedance-release keygen \
  --private-file release-signing-key.b64 \
  --public-file agent-update-trust-key.b64
chmod 600 release-signing-key.b64

make agent-release VERSION=1.2.3 ARCH=amd64 \
  AGENT_UPDATE_PUBLIC_KEY="$(cat agent-update-trust-key.b64)" \
  OUTPUT=dist/nodedance-agent-linux-amd64

nodedance-release sign \
  --binary dist/nodedance-agent-linux-amd64 \
  --private-key-file release-signing-key.b64 \
  --output dist/manifest-amd64.json \
  --version 1.2.3 --architecture amd64 \
  --min-protocol 1 --max-protocol 1 --core-min 1.0.0
```

将 Core 配置为信任的公钥，管理员登录 Web 后上传 manifest 和对应二进制；UI 可逐节点手动更新，或在确认发布和目标节点后开启 UTC 时间窗口及批大小。不得用测试私钥构建生产 release。首次安装旧 Agent 时，先用安装包或受控 SSH 过程安装包含 updater 的二进制，再执行 `nodedance-agent install-systemd --user <service-user> --config <absolute-private-config> --enable`。
