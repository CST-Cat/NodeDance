# S14：HTTP/HTTPS/TCP 服务探测

**前置阶段：** S13。  
**估算：** 3–5 个开发日。  
**当前状态：** `NOT_READY`（功能候选实现及本地自动检查已完成；规范要求的真实远端/失联证据仍待补齐）。

## 本阶段交付

Core 保存探测配置、运行状态和历史；拥有该节点身份的 Agent 主动对目标发起探测，Core 不代替 Agent 发请求，浏览器也不探测目标。Agent 没有新增监听端口。配置及历史使用 SQLite 持久化，配置写操作经过管理员 Session、CSRF 和审计检查，并以 revision 防止旧页面覆盖新配置。

管理员接口：

| 方法与路径 | 行为 |
|---|---|
| `GET /api/v1/probes` | 列出未删除配置 |
| `POST /api/v1/probes` | 为已纳管节点创建配置 |
| `GET /api/v1/probes/{id}` | 读取配置及当前状态 |
| `PUT /api/v1/probes/{id}` | 按 revision 更新、启用或停用 |
| `DELETE /api/v1/probes/{id}?revision=N` | 软删除配置并保留历史 |
| `GET /api/v1/probes/{id}/history?limit=100` | 查询最近运行记录 |

请求样例：

```json
{
  "nodeId": "<已纳管节点 UUID>",
  "name": "Homepage",
  "kind": "http",
  "target": "http://127.0.0.1:18080/health",
  "expectedHttpStatus": 200,
  "intervalSeconds": 30,
  "timeoutSeconds": 3,
  "enabled": true
}
```

`127.0.0.1` 相对于被控节点。HTTP 不跟随重定向；HTTPS 使用系统证书验证；探测直连目标，不读取 HTTP 代理环境变量。单次响应体读取最多 4 KiB；Agent 每节点最多并发执行 4 项探测。请求超时受配置约束。Core 每秒检查到期配置，单批最多 64 项。

服务状态使用 `healthy`、`unhealthy`、`unknown`：三次连续失败进入异常，两次连续成功恢复；未观测、节点离线、能力不可用或本地并发饱和不伪装成健康。离线转换会把当前状态写为 `unknown`、清零连续失败/成功计数、记录一条 `node_offline` 历史，并按配置间隔延后下次检查。重复离线不会重复写入相同离线历史，也不会创建待执行 run。

探测入口位于节点仪表盘；Web 检查以 375、768、1440 CSS 像素视口验证无水平溢出。该浏览器用例的 API 是 Playwright stub，不能作为 API 或后端集成证据。

## 本地及 GitHub Actions 检查

本地完整候选检查：

```bash
make test-s14
```

命令会先检查锁定依赖，再依次执行共享协议、Agent 执行器/并发桥、Core 配置/调度/历史、Core API/真实进程内 Agent 与 Core WebSocket loopback 测试的 Race 及普通测试，最后运行 Chromium 仪表盘导航和响应式检查。GitHub Actions workflow 对完整候选命令执行一次并保存控制台日志为 artifact。失败时定位并重跑受影响的检查；代码变更后重跑相关检查。workflow 通过只表示候选自动化检查通过，不替代下表仍缺失的真实环境证据。

完成门槛仍需满足：全部规范用例在规定环境通过，核心自动化验收完成一次有意义的完整运行；失败和恢复路径可复现；无鉴权绕过、错误节点绑定、数据丢失或未验证结果被报告为成功。环境缺失的用例必须保持 `NOT_READY`，不能因组件测试或 workflow 成功改标 `PASS`。
