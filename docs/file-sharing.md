# File sharing / 文件分享

NodeDance embeds file sharing in its existing file manager and Core. The shared list/grid right-click menu expose **Share** for files and directories; **Manage shares** opens the same workflow. Direct file uploads, clipboard files, expiry, download limits, password protection, direct links, QR codes, system/email sharing, editing, content replacement, owner downloads, revocation and invitation-only file collection use the current account and operation contract. There is no separate Gokapi login, process, service or installation.

文件和文件夹的右键菜单直接提供「分享」，「管理分享」集中查看和修改分享、上传新文件及收集文件。文件夹保留目录层级，接收方浏览目录并逐文件下载；不引导压缩。到期或撤销只影响分享副本，不删除节点源文件。

## Contract and lifecycle / 契约与生命周期

Web, CLI and TUI discover `shares.*` and `share-requests.*` through `/api/v1/operations`. Names, methods, routes, input fields, secret headers and transfer bounds come from Core. No client-owned operation list or independent business permissions are added.

- `shares.create`: node ID, selected absolute paths, name, expiry days, maximum downloads, optional password and a random 64-character lowercase hex `requestId`. Retries use the same request ID and return the created share; reopen management after an uncertain or cancelled request to observe any committed result. No automatic retry publishes another share.
- `shares.upload`: raw file upload, filename/settings/request ID query, optional secret `X-Share-Password` header. It writes sharing storage, never an arbitrary remote path.
- `shares.list/get/update/revoke`: the current administrator's shares; updates and revocation require the observed revision. Omitted password preserves it; an empty password removes it. `replaceId` selects another owned, unrevoked share's content. Expiry days are relative to the update time.
- `shares.download`: owner download without consuming the public allowance.
- `shares.public/unlock/receive/hotlink`: public metadata, password verification, password-bearing download and password-free direct download. A password-protected share never supplies a usable direct link. Public metadata never includes node IDs, source paths, owner IDs, password hashes or blob identities. Before password verification it also withholds the title and file manifest.
- `share-requests.create/list/get/update/revoke/download`: private collection management and owner downloads. `maxBytes` bounds total received bytes; zero means unlimited within per-transfer and entry limits. Revocation removes the collected entries from the request.
- `share-requests.public/upload`: invitation title/notes/limits and raw file upload. Anonymous clients never receive the collected filenames, bytes or private management routes. Concurrent completions recheck current revision, owner, expiry and collection limits before attaching content.

Public pages are `/s/{id}` and `/r/{id}`. Share IDs and invitation IDs contain 256 random bits. Possession of an invitation permits uploading to isolated Core sharing storage; it never grants a filesystem capability. Public responses ignore management cookies. Unsafe browser requests require the configured same origin. Private mutations also retain session/CSRF validation. Password checks have bounded concurrency and a per-address/share attempt limiter.

A public download consumes one allowance atomically when the file is opened for transfer. Visiting metadata, password verification, HEAD requests and owner downloads do not consume it. Separate download attempts consume separate allowances, including interrupted transfers; ranges/resume are not provided by this workflow. Withdrawal prevents subsequent requests; an already-open transfer may finish. Downloaded copies cannot be recalled.

Creating a node share reads through the existing root Agent policy and verified file-transfer channel. Symlinks, traversal, protected credential/runtime trees and nonregular files are rejected. Content is stored under the owner-protected Core `shares` directory as `0600` SHA-256-addressed blobs; duplicate content shares one blob. Node shares are snapshots: source changes/deletion do not silently change the published bytes. Revoking/removing the source node or disabling/removing/demoting the owner prevents public access on the next request. Offline Agents do not prevent snapshot downloads. Source file deletion alone does not revoke an intentionally published snapshot; use Revoke share.

There are at most 1,000 unrevoked share records, 1,000 unrevoked collection records and 1,000 entries per record; node snapshots have maximum depth 64, at most 100 selected roots and the configured Agent transfer limit across their contents. Direct uploads retain the Core transfer limit. Four node snapshot creations, invitation uploads or direct uploads may run concurrently. Node snapshot creation has a maximum 30-minute lifetime and does not hold the management mutation lock during transfer, so unrelated revocations remain available. Unreferenced or expired blob content older than one hour is cleaned hourly; live deduplicated references and unrevoked collected files are preserved. Metadata remains available to its owner for observation; lists return at most 1,000 records, prioritizing unrevoked records. Revoking a record frees its creation slot. Stored bytes are protected by filesystem permissions and HTTPS in transit; this change does not implement end-to-end or storage encryption.

## Verification / 验证

`make build` refreshes embedded assets and both binaries. `node web/scripts/audit-files.cjs` includes `audit-shares.cjs` against isolated real Core/root Agent fixtures, installed dialogs, a separate anonymous Chromium context, public folder browsing, QR generation, owner/public download counting, concurrent limits, password protection, stale edits, safe paths, explicit uploads and private collection. `NODEDANCE_GUEST_ATTACKS=1 node web/scripts/audit-guest.cjs` discovers the expanded private contract and attacks share queries, methods, host paths and withdrawal. Store regressions verify deduplication, password checking, atomic download admission, collection bounds and cleanup without removing live blobs. Tests do not access production data or remote resources.
