# NodeDance repository rules

- Treat the current product behavior as the only implementation. Do not add compatibility branches, adapters, migrations, or tests solely for retired modes, APIs, or behavior. Remove deprecated duplicate code and documentation when it is in scope.
- Agent enrollment, recovery, runtime, file service, and systemd service are root-only. Do not generate or support a non-root restricted Agent or file-service mode.
- Agent releases use the `agent-vMAJOR.MINOR.PATCH` tag namespace (for example, `agent-v0.1.0`). Only those tags trigger the Agent release workflow; Core release tags use a separate namespace. Installer commands must resolve and pin a published Agent tag rather than use a repository-wide `latest` release URL.
- Preserve current security requirements: Agent credentials must remain owner-protected in a `0700` state directory and `0600` regular config file; file management must reject traversal, symlinks, Agent credential paths, and protected kernel/runtime trees.
- Tailscale is an optional network capability. NodeDance may detect it and expose the existing Agent installation entry when available. Agent installation remains root-only. NodeDance does not install or configure Tailscale or change its configuration.
- Work directly on `main`; do not create branches.
- Every new or changed product capability must be implemented consistently in Web, CLI, and TUI. Keep CLI and TUI as downstream abstractions of the Core API and shared operation catalog; share request schemas, validation, permissions, and behavior instead of maintaining separate business logic. A change is incomplete until all three interfaces expose the applicable functionality, their documentation is updated, and interface synchronization is verified.
- The connected Core publishes the single operation contract at `/api/v1/operations`. Web, CLI, and TUI must discover operations, request schemas, methods, routes, and transports from that contract. New Core capabilities must appear automatically in their generic operation interfaces; specialized screens are presentation only. Do not maintain independent client operation lists or duplicate business validation.
